# ZigZag 0.1.3

Choose your machine, satin lettering from filled letters, a shortest stitch
and lock stitches for machines that need them, more hoop sizes, and a
custom hoop.

## Updates

- ZigZag looks for a newer release when it opens (and once a day), and an
  Update button appears in the toolbar when there is one. The window
  says what's new; on a Mac, Install and Relaunch downloads it, checks
  it, puts it in place of the copy that's running and opens it, with your
  documents as you left them. On Windows and Linux it opens the download.
- An update is only installed if it matches the release's checksum and
  is signed, intact, by the same developer as the ZigZag that's running.
  The new app and the old change places in one step, so a failed update
  leaves the old one as it was. If ZigZag can't replace itself (it's
  running from the disk image, or the folder can't be written to), it
  says so and offers the download.
- ZigZag › Check for Updates… (in Help on Windows and Linux) looks now.
  Settings › General › Updates turns the automatic look off. It asks
  GitHub for the latest release and sends nothing about you or your
  designs.
- This is the first version that can update itself: from 0.1.2, download
  it once more.
- On a Mac, ZigZag can also be installed and kept up to date with
  Homebrew: `brew install --cask simpsoka/zigzag/zigzag`.

## Locking, hiding and selecting

- The Objects list has an eye and a lock at the left of every row, as in
  Illustrator's Layers. Click the eye to hide an object: it isn't shown
  or sewn, and keeps its stitch settings for when it's shown again.
  Click the lock to lock one: it can't be selected or moved (a
  background, so the pointer goes through it to what's on top), and sews
  as usual. Option-click does it to every other object instead. Both are
  saved in the file.
- Object › Lock (⌘2), Unlock All, Hide (⌘3) and Show All.
- Dragging the Selection tool over empty canvas draws a box, and
  everything it touches is selected (Shift adds to what already is). It
  used to move the canvas.
- To move the canvas: scroll with two fingers on a trackpad, hold Space
  and drag, use the Hand tool, or drag with the middle or right button.
  A mouse's wheel and a pinch still zoom; so does ⌘ and a scroll.
- Agents: `set_object`'s `hidden` and `locked`.

## Machines

- The Document panel has a Machine menu. Choose yours and its hoops lead
  the Hoop menu, Export offers the file it reads first, and new documents
  start set up for it.
- ZigZag comes with nine: the Brother Skitch, Brother's 4×4, 5×7 and PR
  machines, Janome's Memory Craft 550E, Husqvarna Viking's Designer Jade
  35, Melco's Summit, ZSK's Sprint 8, and one for any commercial machine
  that reads DST. Only the Skitch has been sewn on from ZigZag; the others
  take their hoops and formats from the makers' own pages (hover the menu
  to see where).
- Machines of your own are made in Settings (the gear beside the Machine
  menu, or Machine Settings… in it): + starts one from the document's
  hoop, and Duplicate copies one of ZigZag's to change. Give it a name,
  its hoops, the file it reads, a shortest stitch and its lock stitches.
- Send to Skitch (the toolbar's needle, and File › Send to Skitch…) is
  there for a machine ZigZag sends to: the Skitch, a copy of it, or one of
  your own whose Connection, in Settings, is Bluetooth (Brother Skitch).
  For a machine that takes a file it's left out of the toolbar and greyed
  in the menu, and Export is how the design gets there. A document set up
  for no machine goes by the one new documents start on.
- A new install starts new documents on the Skitch, until you choose
  another machine (or none) in the Document panel or Settings.
- A machine is a name for ordinary settings, which are saved into the
  design. A file opens the same on a computer without that machine, and in
  earlier versions.
- Agents have `list_machines` and `set_document`'s `machine`; `export`
  without a format writes the file the document's machine reads. The
  command line has `--machine` and `zigzag machines`.
## Settings

- ZigZag › Settings… (⌘, ; at the foot of Edit on Windows and Linux) has
  what's set once for this computer: Machines, General (units, light or
  dark, drawing stitches on the GPU) and Agent (which agent the Agent
  panel runs, and whether other agents can connect and on which port).
- Draw Stitches on GPU has moved there from the View menu, and is now
  remembered. Light or dark, and the agents' port, used to need an
  environment variable or a launch option; those still work and win.

## Satin lettering

- A filled shape set to Satin that isn't one column is now cut into
  columns where its branches part, instead of being filled: a P into its
  stem and bowl, a T into bar and stem, an E into stem and bars, letters
  with counters, and strokes that curl round on themselves (a C). Block
  shapes become straight columns butted together; a column turns a sharp
  corner only where nothing else will do. If a shape can't be cut into
  columns whose stitches stay inside it, it's filled as before, with a
  note. Designs with such shapes will sew differently from 0.1.2: as the
  satin they asked for.
- Lean, in the Stitch panel (`lean=8` in an id, `lean` for agents), leans
  a satin's stitches from square across the column, up to 60° either way.
  At a column's ends they fan from the corner, so nothing is left bare.
- Travel can run under the satin that's about to be sewn, as well as
  under what's sewn later, and an object's last piece is sewn toward the
  end the next object can be reached from. Lettering sewn stroke by
  stroke is cut only between letters when each stroke is followed by one
  that covers the way to it.
- The thread no longer runs over a fill's finished rows to get from one
  part of it to the next. Three things changed:
  - A row or two at a wavy or slanting edge stays part of the section
    beside it (joined along the rows), instead of being split off and
    sewn after everything else.
  - A fill's sections are sewn in the order, and each the way, that lets
    the thread travel under rows still to come. (Up to six sections;
    more than that are sewn nearest first, as before.)
  - Where there's still no way that's out of sight, the thread is cut.
    Before, it was sewn straight across the fill or round the inside of
    its edge, on top.
  Designs with fills in several sections will sew differently, often
  with more trims: across nineteen designs tried, 189 trims became 228
  (eight designs unchanged, two with one fewer, nine with more), and
  travel that showed in eight of them shows in none but for a
  millimetre or two in two.
- Travel › Sew over fill, in the Document panel, puts it back: the thread
  is sewn over the fill instead of cut where it can't be hidden. As many
  trims as before (189 for the same nineteen designs), and running stitch
  on top of the fill where there's no other way. Agents:
  `set_document`'s `over_sewn`; command line: `--over-sewn`.
- The design checks say when travel shows: "The thread crosses N rows of
  stitches already sewn…", worked out from the stitches themselves.
- Travel between a satin's columns no longer runs back through a column
  that's already sewn (it showed as a line of running stitch down the
  middle of the finished satin). It hides under the columns still to sew
  and what's sewn later, or the thread is cut.
- A two-rail satin can be given as one stroked path whose two longest
  subpaths are the rails and whose shorter ones are rungs (it could
  before; the agents' `add_svg` now says how).

## Shortest stitch and locks

- A machine's Min stitch, in Settings, says how short a stitch may be,
  for machines that drop short ones. Nothing in the preview or the exported
  file is shorter. Fill rows closer together than the minimum are sewn
  every second row and then the rows between: the same needle points and
  coverage, with turns long enough to keep. Other short stitches (at tips,
  where pieces join, after rounding to the file's units) are merged into
  their neighbours.
- A machine's Locks are the tie-in and tie-off stitches in exported files: back
  and forth, a triangle, or none, with each stitch's length and how many.
  A lock stitch is never shorter than the minimum. (Files for the Skitch
  keep the locks they had.)
- Choosing a machine sets both for the design, and the Document panel
  says so under the Machine row. Brother's PR, Melco's Summit and the
  commercial DST machine have a 0.4 mm minimum.
- Both are saved in the design only when they aren't the usual (0.1 mm,
  four 0.4 mm stitches back and forth). Designs without them sew as
  before, except that needle points closer than 0.1 mm where two pieces
  join are now merged.
- Agents: `set_document`'s `min_stitch_mm` and `lock`. Command line:
  `--min-stitch` and `--lock`.

## Also

- The Stitch panel shows every stitch type for the selected object, each
  always in the same place. The ones a line can't take (Fill, Contour and
  the others that cover an area) are dimmed, and say why when you point at
  them; before, they were left out.
- The machine window's Before You Sew checklist folds away: click its
  heading. Sections that fold (Before You Sew, Machine Details, the MCP
  chip's Tools) stay as you left them the next time ZigZag opens.
- The machine window's Send card is laid out as the panels are:
  Placement and Trial Run as rows with their names in one column, and
  Send Design the width of the card.
- Agents can name an object by the id they gave it in an SVG
  (`Face_mask`, or the whole `Face_mask_fill_a=45`) as well as by the name
  ZigZag shows ("Face mask"). An agent that drew a design and then
  restyled it by its own ids was told there was no such object.
- Every agent tool has been run against what it says it does. Fixed:
  lettering with a horizontal or vertical scale couldn't be edited again
  (in the Lettering panel too); `export` without a format now goes by
  what the path ends in before the document's machine; `save` only writes
  `.svg`; opening a file ZigZag can't read (a VP3) says what it can;
  `round_corners` and `simplify` take one object as well as a list;
  `get_design` reports `connect_mm`; `list_fonts` leaves out the system's
  hidden fonts; a batch step that isn't `{tool, arguments}` says so; and
  settings of the wrong sort (a size that isn't a number, a `fit` that
  isn't one) are refused instead of passed over.
- ZigZag keeps a log of every tool call agents make: when, which agent
  connected last, the document, the tool, what it was asked and what it
  answered (or why it failed), one line of JSON a call. Show Log, in the
  status bar's MCP chip and in Settings › Agent, opens it; Settings turns
  it off. It stays on this computer (`agent-log.jsonl` in ZigZag's
  settings folder; it starts again at 8 MB). The chip's recent calls also
  show what each was called with when you point at them.
- When a tool refuses one of Codex's calls, the Agent panel says why (it
  said only that the call failed).
- Help › Report an Issue… opens a new issue on GitHub in your browser,
  started with which ZigZag you have and what it's running on.
- Double-click an object's name in the Objects list to rename it, as in
  Illustrator's Layers. Enter keeps the name, Escape doesn't. A single
  click only selects, however soon after another. The name is saved in
  the SVG as the element's id, with its stitch settings after it as
  before; a name can't be a stitch setting itself (`satin`, `trim`).
- Narrow satin, in the Document panel, says how narrow a satin may be before
  it's warned about (it was always 1 mm). A column that sews cleanly on
  your fabric at 0.9 mm needn't be flagged. Agents: `set_document`'s
  `narrow_satin_mm`; command line: `--narrow-satin`.
- Agents can ask any tool that changes the design for a short answer with
  `terse: true`: ok, the names of objects added, and the design problems
  that are new, instead of the whole object. On `batch` it covers every
  step, and steps that only read (such as `check_design`) keep their
  results.
- `export` with `objects: true` (command line: `--objects`) writes
  `FILE.objects.json` beside a machine file: the objects, and which
  object each stitch, jump and trim in the file is for, so a checker can
  point at the shape behind a fault.
- The command line's help and the agents' tools now say that WebP, GIF,
  BMP and TIFF logos are traced as well as PNG and JPEG (they were).
- Travel round the inside of a fill's outline no longer starts with a hop
  across open cloth in shapes with parts too thin for it (the terminal
  of a small serif letter): it goes another hidden way, or the thread is
  cut.
- Fill rows widened for pull compensation (as on knits) are joined into
  sections like any others. They were sewn the same, but each row was
  planned as a piece of its own.
- `add_svg` and `trace_image` with `replace` now keep the document's
  settings (fabric, hoop, machine, preview color) instead of putting them
  back to the defaults.

## Hoops

- The Document panel's Hoop menu has ten standard sizes, from 1×2.5 in
  (20 × 60 mm) to 9.5×14 in (240 × 360 mm), with the Skitch's two frames
  and Janome's A and B.
- Custom takes any width and height (10 to 1000 mm a side), for magnetic
  and other frames. The canvas, the fit check and Fit to Hoop all use it.
- The hoop is saved in the file as its size. Files from earlier versions
  open with the hoop they had; an earlier version opening a file saved by
  this one shows it in the 4×4 hoop (the stitches are the same).
- Agents can set any size with `set_document` (`"hoop": "150x220"`), and
  the command line's `--hoop` takes `130x180` or one number for a square,
  defaulting to the hoop saved in the file.

## Install on Mac

Download **ZigZag.dmg**, open it, and drag **ZigZag** into **Applications**.
Or, with Homebrew: `brew install --cask simpsoka/zigzag/zigzag`.
Requires macOS 11 or later; one download supports Apple Silicon and Intel.
The app and DMG are signed and notarized by Apple.

`ZigZag-0.1.3.dmg` is the same download with the version in its filename.
`SHA256SUMS.txt` contains checksums for both filenames.

## Install on Windows

Download **ZigZag-0.1.3-x86_64-windows.zip**, unzip it, and run
**ZigZag.exe**. Windows SmartScreen may warn the first time: choose
**More info** → **Run anyway**.
