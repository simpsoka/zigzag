# ZigZag 0.1.10

The Agent panel sets itself up: pick an AI assistant, install it and
sign in from the panel, with no terminal. Google's Antigravity joins
Claude Code and Codex; and Jump Stitches and Smart Guides stay as you
left them.

## Setting up an agent

- The Agent panel has a **Setup** page (the first time you open it, from
  the agent menu in its header, and whenever the agent you chose isn't
  installed). It lists each assistant ZigZag works with, who makes it and
  the account it needs, with a link to a guide for choosing one.
- **Install** runs the maker's own installer for you and shows its
  progress; an install that fails says why and can be tried again. The
  terminal commands are still there, folded under *Install from a
  terminal instead*, with Check Again.
- An assistant that's installed but not signed in shows **Sign In**
  instead of the prompt: it opens the sign-in page in your browser and
  finishes by itself once you've signed in. Where the page gives a code,
  there's a field to paste it into. A turn that fails for want of
  signing in brings the same card up above the prompt.
- The panel opens on the agent you used last; if that one isn't on this
  computer, on the first that is.
- The install commands shown are each maker's current ones (Codex's own
  installer first, then Homebrew or npm).

## Antigravity

- Google's **Antigravity** (`agy`) is a third agent, beside Codex and
  Claude Code: choose it from the agent menu or with `/agent antigravity`.
  Like the others it can use only ZigZag's design tools: its shell, file
  writes and the web are refused.
- Images attached to a prompt go with it. Its effort can be chosen, and
  a model named with `/model`.

## Working with an agent

- A prompt sent while the agent server isn't running says why: another
  copy of ZigZag holding the port, the server turned off in Settings, or
  `--no-mcp`.

## View

- **Jump Stitches** and **Smart Guides** are remembered: turn one off and
  it stays off for every document, and the next time ZigZag opens.

## The file checker's engine

- The engine behind the file checker on zigzag.diy is now part of
  ZigZag's library. Reading a PES, PEC, DST, EXP or JEF, it keeps where
  the thread was trimmed and notes what's wrong with the file itself:
  one cut short, a code ZigZag doesn't know, a header that lists a
  different number of threads than the stitches use.
- It fixes what can be fixed from the stitches alone: same-thread blocks
  sewn one after another are joined, stitches that go nowhere taken out,
  stitches too long to sew split, thread carried across the design cut,
  and pieces with no tie stitches tied off (only those: a piece with its
  own keeps them). The fixes follow the format the file is saved in, so
  a JEF, which holds no trims, isn't said to have gained any.

## For developers

- `packaging/windows/build-from-mac.sh` cross-compiles the Windows
  executables on a Mac, to try the interface in a Windows VM before a
  release (see RELEASE.md).
